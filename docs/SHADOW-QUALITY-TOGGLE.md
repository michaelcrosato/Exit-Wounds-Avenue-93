# Quality-switch shadow lifecycle regression and app fix

On prior runtime source `928d93c`, the player-visible Settings control reproduced a renderer failure: High → Low → High disabled an established Three r182 shadow target, then the next High draw logged `Cannot read properties of null (reading 'depthTexture')` in `ShadowNode.updateShadow`. The UI could still say Playing while world frames stopped. Published production-fix commit **`e6426f64a18dcb9ae77e324e0c37b480afce84b6`** integrates the app adapter below and passes source-browser WebGL2 and WebGPU switch regressions; a packaged-release/repeated-run result remains separate. This renderer bug is distinct from the diagnosed Rapier SIMD body-lifecycle trap in [ENGINE-PATCHES.md](ENGINE-PATCHES.md).

Normal Pause → Settings UI switching reproduced the same error in an isolated WSL Chromium 153 **WebGL2** context; its frame count stalled on the first Low → High transition. Raw browser record: `/tmp/ewa-shadow-quality-ui-2026-10-17T00-31-18-845Z/report.json`. An isolated Windows Chrome 155 **WebGPU** context on CDP 9223 also failed High → Low → High with frames stalled at 140; raw record: `C:\Temp\EWA93ShadowWebGPUTrial\report.json`. A cold Low profile happened to survive Low → High → Low → High on the unchanged source; that pass does not make the High-start sequence safe. Both trials kept source hashes unchanged. Their coarse original `status` fields should not be treated as acceptance: inspect the captured console error and frame counter for the normal path.

[Three r182 ShadowNode](https://github.com/mrdoob/three.js/blob/r182/src/nodes/lighting/ShadowNode.js) dereferences its shadow render target in `updateShadow()` and clears that target when disposed. [AnalyticLightNode](https://github.com/mrdoob/three.js/blob/r182/src/nodes/lighting/AnalyticLightNode.js) disposes a shadow node when `castShadow` becomes false. In the published e6 code, `app.applySetting('quality')` toggled `world.shadows`, and `World3D._light()` used that value to toggle the authored sun's `castShadow`. This source path and matching error make disposed shadow-node reuse the leading explanation; no vendored Three patch is applied.

A **runtime-only** workaround was tested before the app fix: keep `world.shadows` and the sun's `castShadow` true; in Low set `light.shadow.intensity=0`, `autoUpdate=false` and `needsUpdate=false`, then restore intensity and updates in High. Two Low ↔ High cycles rendered without errors in WebGL2 (`/tmp/ewa-shadow-quality-ui-2026-10-17T00-31-18-845Z/report.json`) and WebGPU (`C:\Temp\EWA93ShadowWebGPUTrial\report.json`). A separate WSL WebGL2 attenuation check at `/tmp/ewa-shadow-attenuation-2026-10-17T00-37-28-505Z/report.json` measured **zero** sun `shadow.updateMatrices` calls over 4–5 live Low frames, versus 5–6 calls in High; the sun's direct light intensity remained **1.35**. Last-frame draw calls were **259 Low versus 362 High** in that fixed view. Low shadow attenuation was zero, and High restored one. The authored scene has zero bootstrap `_shadowLights`; the integrated adapter applies properties to any bootstrap light but does not itself stabilize future dynamically selected torch casters.

## Integrated narrow app adapter

[`src/engine/world.js`](../src/engine/world.js) now constructs `World3D` with stable **authored-sun** shadow-caster identity even when a saved profile starts Low. It captures bootstrap lights' original shadow intensity/update settings and exposes `runtime.setQuality(quality)`: Full render resolution for High, Balanced otherwise; `world.shadows=true` so `World3D._light()` does not flip the sun's `castShadow`. Low sets the sun and any bootstrap `_shadowLights` shadow intensity to zero and turns off `autoUpdate`/`needsUpdate`. Medium/High restore saved intensity/update settings and request a fresh update. Direct sun intensity remains unchanged. `src/main.js::applySetting` calls this adapter instead of assigning `world.shadows=false`. The current authored scene has `_shadowLights=[]`; the engine can dynamically change torch caster identity if torches are later added, so that future setup needs separate testing. The fix stays within the pinned engine and skips Low sun shadow-map work. Medium is implemented but the focused runner exercises Low and High only.

## Regression runner

[The focused test](../tests/e2e/shadow-quality-toggle.mjs) uses normal New Game, Pause, Settings select, Back and Resume actions. It checks High → Low → High twice from a High boot and Low → High → Low → High from a fresh Low profile. It asserts the requested renderer backend, advancing world frames and simulation ticks after each switch, zero page/console/network errors, stable source hashes, unchanging direct sun illumination, Low shadow intensity/update suppression with zero actual shadow-matrix calls, and restoration of High shadow work. If the authored world gains torch casters, the same property and update checks cover them. It writes JSON and a failure screenshot outside the repository.

Run WebGL2 on WSL with the integrated adapter:

```bash
PLAYWRIGHT_HOST_PLATFORM_OVERRIDE=ubuntu24.04-x64 \
EWA93_SHADOW_BACKEND=webgl \
node --test --test-concurrency=1 tests/e2e/shadow-quality-toggle.mjs
```

For an available hardware WebGPU browser, start a source server and attach to its isolated Chrome CDP endpoint with `EWA93_SHADOW_BACKEND=webgpu`, `EWA93_SHADOW_CDP_URL` and `EWA93_SHADOW_BASE_URL`; select an out-of-repository `EWA93_SHADOW_OUTPUT`. The test fails if requested WebGPU falls back to WebGL2. Run browser jobs serially on the WSL software renderer.

The **e6426f6 source-build** regression passed both recorded sequences in [WebGL2](evidence/shadow-quality-webgl2.json) and [WebGPU](evidence/shadow-quality-webgpu.json): repeated High → Low → High from a High boot, and Low → High → Low → High from a cold Low profile. Each backend has **2/2 passing records**, zero page/network errors and stable before/after source hashes. In the final High stage, frames and fixed ticks advanced, the sun remained a shadow caster at direct intensity 1.35, shadow intensity/update work resumed, and no app error appeared. Low stages retained direct illumination while shadow intensity was zero and matrix updates stopped. Raw reports are `/tmp/ewa93-shadow-quality-fixed-webgl/report.json` and `C:\Temp\EWA93ShadowFixedWebGPU\report.json`. These are source-build browser checks, not a packaged-release pass or proof of every possible repeated quality cycle. The original failing records above remain unmodified.
